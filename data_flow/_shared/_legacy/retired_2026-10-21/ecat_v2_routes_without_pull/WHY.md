# ECAT ratings re-run because the routes refuted instead of explaining the pull

Measured across these outputs: **299 of 362 trap routes said only that the option is wrong, and 63
said what draws a student to it.**

A wrong option is not a trap. A trap is a wrong option a PREPARED STUDENT REACHES FOR, so a route
that only refutes leaves the label unexplained — the reader can already see the option is wrong;
what they cannot see is why anyone would pick it.

> "Says the configuration is kept. The front face is the one the departing group shields."

True, and it never says why a student would think the configuration is kept. The pull is a
half-remembered rule — "SN1 goes through a flat carbocation" — and naming it is what makes
`semantic_reversal` a demonstrated label rather than an asserted one.

**This was my instruction, not the raters'.** An earlier run produced 60-word routes that argued for
the label, so I added "never explain why the label fits". That over-corrected: I conflated arguing
for the label (meta, useless — the definition is printed directly above the route) with naming the
pull (substantive, and the evidence the rulebook actually requires). The brief now separates the
two explicitly, with corrected before/after pairs.

The LABELS here are sound — every value inside allowed_values, no trap on any key, every option
named. Kept so a changed label in the re-run can be compared against them.
