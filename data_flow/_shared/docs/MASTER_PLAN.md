# NEET PYQ Pipeline — Master Plan (as of 2026-10-10)

This is the single reference document tying together everything decided and built so far: what data we actually have, what every category/tag means, how each stage of the pipeline works against that real data, where Physics/Chemistry/Biology need different treatment, what's genuinely built and tested versus still pending, and whether this architecture actually delivers the thing it's for. It supersedes scattered findings in `docs/OPEN_QUESTIONS.md` by organizing them into one plan — `OPEN_QUESTIONS.md` stays the append-only decision log; this document is the current-state map.

---

## 1. What this is for (don't lose sight of this)

Everything below exists to serve one feature: a student uploads an NCERT textbook page, and the system builds a practice test from **real past NEET questions on that exact subtopic**, in the formats NEET actually uses today. That only works if every question in the bank is (a) copied exactly with a checked answer, (b) linked to the precise NCERT subtopic and sentence that proves the answer, and (c) tagged with its format and thinking demand accurately enough to assemble a test that feels like a real recent paper. Section 8 of this plan checks whether what's built can actually deliver that.

#### 2.1.1 What "scraped, not official" means operationally — the rules that make the accepted data usable anyway

Confirmed across all 10 inspected papers:
1. **Every paper file has the answer and a third-party worked solution embedded in it.** → **Rule: B6 (blind solver) and D7 (latest-answer checker) must never be given these paper files directly as their "no key" input** — if the pipeline is built against these files as-is, B6's entire value (an independent check against misreads) collapses, because the "blind" solver would see the answer sitting right there in the page. Before B1/B6 are built for real, the ingestion step must either (a) strip the answer/solution overlay before handing a page to any agent, or (b) source genuine NTA scans. This is the single highest-priority fix needed before Stage B can be trusted — flagged again in §7.
2. **Embedded "correct answers" are measurably wrong at a meaningful rate** — mismatch rates against the real key ranged 7% (Biology) to 48% (Physics) across papers, worse in numerically-heavy subjects. → **Rule: the real key PDF is the only trustworthy answer source, never the paper file's own highlighting.** B5 must join on `(paper_id, qno)` against the key file, full stop.
3. **Image-based options/figures are not preserved** — confirmed missing or placeholder-text across every paper checked. → **Rule: no figure-dependent question (`figure_role: needed`, `structure_options`, `graph_options`, `diagram_labelled`) can be fully processed from these paper files alone.** This is the second-highest-priority fix — see §7.
4. **At least one fabricated-looking booklet code** was found (2021's `GAJAHA-M1`, absent from the real key's actual codes M1/N1/O1). → **Rule: `booklet_code` must always be read from the paper's own printed content during B1, never trusted from a folder/file name.** (Already true per spec Rule 13; just confirmed as load-bearing, not theoretical.)
5. **Missing questions, duplicated/garbled text, cross-code contamination** — all confirmed, all exactly the kind of thing B2–B4's checks are designed to catch. No new rule needed beyond "run the checks for real, don't skip them because the source looks clean."

**Net effect of the decision to proceed anyway:** Stage A (NCERT indexing) is unaffected by any of this — it reads genuine NCERT files, confirmed clean (§2.2). Stage B (paper extraction) can still be built and even partially run, but **should not be treated as producing a trustworthy Layer-1 bank until the answer/solution overlay and missing-figure problems are addressed** — building the scripts and agents is fine now; releasing data built from them is not, until that's fixed.

## 3. Complete taxonomy — v0.2, as it actually stands today

This is the full, current state of `config/allowed_values.yaml`, after the 10-paper validation pass. Treat this table as authoritative over any earlier version referenced in chat.

### 3.1 E1 `question_type` (18 values)
single_statement, statement_options, list_of_statements, statement_i_ii, assertion_reason, match_the_lists, match_three_columns, pair_options, arrange_in_order, rank_by_property, fill_in_blank, diagram_labelled, figure_to_read, graph_options, structure_options, reaction_scheme, multi_part_respectively, **list_of_structures** (new v0.2 — a list whose items are structures/figures to judge/count, not text statements), plus `new_type`.
Rules: an A/B-labelled two-statement item is `statement_i_ii` regardless of label style; a question may carry two E1 tags at once (e.g. `fill_in_blank` + `figure_to_read`).

### 3.2 E2 `format` (25 values)
pick_correct, pick_incorrect, count_correct, pick_correct_combination, pick_match_code, pick_order, odd_one_out, calculate_value, derive_expression, pick_ratio, pick_proportionality, name_or_identify, identify_structure_or_compound, predict_product (forward direction only), **identify_reactant** (new v0.2 — backward direction: given products, find the reactant), identify_reagent_or_condition, identify_reaction_or_process_name, classify_into_group, pick_explanation, predict_effect, pick_graph, judge_two_statements, judge_assertion_reason, pick_scientist_or_date, expand_abbreviation, plus `new_format`.

### 3.3 E3 `content_shape` (29 values)
one_line, list, example_list, table, diagram, labelled_diagram, graph, formula, derived_result, experiment_classic, practical_procedure, comparison, process, cycle_or_pathway, life_cycle, exception, classification_hierarchy, definition_term, trend, reaction_mechanism, structure_chemical, nomenclature_rule, value_or_data, scientist_history, applied_context, biological_equation, disease_cause, current_affairs, plus `new_shape`.

### 3.4 E4 `thinking` (8 fixed + 9 unpromoted candidates) — the most important tag to get right
recall, elimination, process, confusion, reasoning, diagram_graph, application, numerical.
Candidates not yet promoted: trend_ranking, classification, proportional_reasoning, estimation, symbolic_derivation, spatial_structural, data_interpretation, experimental_reasoning, multi_concept.

**Three confirmed rules, each validated against 10 real papers independently — these are the single most load-bearing findings of the whole validation pass:**
1. **Chemistry's thinking prior must be conditioned on B7's branch output (physical / organic / inorganic), never on "Chemistry" as one subject.** Physical-chemistry questions behave like Physics (numerical/application-dominated); organic/inorganic behave like Biology (recall/elimination-dominated). Confirmed 10/10 papers, no exceptions.
2. **Biology is rarely numerical, not never.** PCR's 2ⁿ and dihybrid-cross ratio questions are real counter-examples.
3. **`thinking` cannot be shortcut from `question_type`, `format`, or subject — ever.** Confirmed both directions: a Physics Assertion-Reason item needed a real calculation inside the A/R judgement (not just "reasoning"); a Biology item that *looked* numerical ("how many molecules of ATP and NADPH") was pure memorized recall with zero calculation.

### 3.5 E5 `trap` (19 values)
look_alike_term, wrong_pairing, half_true, wrong_order, ignores_exception, extreme_word, old_ncert_fact, opposite_answer, calculation_slip, swapped_positions, number_near_miss, unit_conversion_slip, sign_or_direction, scientist_swap, name_variant, invalid_comparator, impossible_value, reversed_cause_effect, partial_combination, plus `new_trap`.

### 3.6 E6 descriptive (script-derived, not agent-judged)
stem_context, answer_form, negation, item_count, constants_given, figure_role.

### 3.7 Validation coverage note
~500 questions sampled across 2016–2025 (one full paper per year, all three subjects). Only 2 genuine taxonomy gaps found in that whole sample (both narrow, both Chemistry-specific — the two v0.2 additions above). **The taxonomy structurally holds up well; the risk isn't missing categories, it's misapplying E4 by subject-level shortcut**, which is why rule 3.4.3 above is the one to enforce hardest in the actual E4 agent prompt and codebook when it's written.
