## 1. THE ITEM IS ONE WRONG OPTION, NOT THE QUESTION

Read this twice. E5's item is **one wrong option of one question**, and the step runs **once per wrong option** — normally **three per question**, each tagged twice (two runs) and adjudicated on disagreement.

- You receive **one** `wrong_option` (number and text). Tag **one** trap for **that** option.
- **Never tag the correct option.** There is no trap on the answer.
- Never tag "the question's trap". Three wrong options of one question routinely carry three *different* traps, and that difference is the whole point of this tag — it is what lets a generated practice test reproduce the distractor profile of a real paper.
- Do not coordinate with the other options. If two wrong options genuinely work the same way, they get the same value; that is fine and not a redundancy.

**How many wrong options a question actually has** depends on `official_status`:

| `official_status` | Wrong options | E5 runs |
|---|---|---|
| `normal` | 3 | 3 |
| `multiple_accepted` | fewer than 3 (two or more options were accepted) | one per genuinely wrong option only |
| `bonus`, `dropped` | not meaningful — the question is broken | skip unless B8 produced a `corrected_answer`, then treat that as the answer and tag the remaining options |

The "3 per question" in SPEC is the normal case, not a quota to fill. **Never invent a third wrong option to reach three.**

**The answer to judge against** is `latest_answer` (what students are taught) — SPEC 12's rule: `corrected_answer` if B8 made one, else `official_answer`, and D7's `latest_answer` once it has run. If an option is wrong against the official answer but right against the latest NCERT, that is not a trap, that is `D7_ANSWER_CHANGED` territory. Say so in `why` and set `confidence: low`.

## 2. How to decide

1. Work out **why this option is wrong**, against the evidence.
2. Then ask the real question: **why would a prepared student pick it anyway?** A trap is an attraction, not just an error. If an option is wrong in a way no student would be drawn to (a random unrelated term), say so in `why` and choose the closest value with `confidence: medium` — do not manufacture a mechanism.
3. Prefer the **specific** value over the general one. `number_near_miss` over `calculation_slip` when no identifiable slip produces it; `wrong_pairing` over `wrong_pairing` when exactly two partners are exchanged.
4. `why` must name the mechanism concretely and in one sentence. "Forgot to square the length ratio: 4 × 2 = 8" is checkable. "Looks plausible" is not.

## 3. The values

### Term and wording traps

**`look_alike_term`** — the option names a **different** thing whose name resembles the right one.
- **vs `name_variant`:** different concept, similar name → `look_alike_term`. Same concept, different name form → `name_variant`.
- **Real example:** in `Q-000015`, statement B says menopause where the fact is menarche. Menopause is a real, different event with a confusably similar name. Any wrong option whose selection depends on that confusion is `look_alike_term`. (B6, solving blind, independently caught exactly this — real evidence that the trap works.)

**`name_variant`** — the option is an alternative, older or loose name for something, so a student who remembers the name imprecisely accepts it.
- vs `look_alike_term`: ask whether the two names denote the *same* thing.

**`scientist_swap`** — a different scientist (or a different date) is named.
- vs `look_alike_term`: use `scientist_swap` whenever the swapped entity is a person or a date, even if the names resemble each other.

**`overclaiming_quantifier`** — "always", "never", "all", "only", "none" turns an otherwise-true claim false.
- **vs `half_true`:** here the *content* is right and a single absolute word breaks it. In `half_true`, part of the content itself is wrong.
- Note the interaction with E6 `negation`: the trap is in the **option**; negation records a negative in the **stem**. Different things.

**`half_true`** — part of the option is correct and part is not.
- vs `ignores_exception`: `half_true` is internally wrong. `ignores_exception` is correct as a general rule but wrong for *this* case.

**`ignores_exception`** — the option applies NCERT's general rule to the one case NCERT excepts.
- **Pairs with** E3 `exception`: if the evidence shape is `exception`, expect at least one option to be this.

**`invalid_comparator`** — the option compares or ranks on the wrong basis: ordering by size when the question asks about energy, or comparing two quantities that are not comparable.
- vs `reversed_order`: `reversed_order` has the right basis and the wrong sequence. `invalid_comparator` has the wrong basis altogether.

**`semantic_reversal`** — the option is the converse of the right answer: increases instead of decreases, exothermic instead of endothermic.
- vs `sign_or_direction`: reserve `sign_or_direction` for a **numeric sign or a vector/physical direction**. Use `semantic_reversal` for a conceptual converse.
- vs `semantic_reversal`: that one swaps cause and effect, not the polarity of an outcome.

**`semantic_reversal`** — cause and effect are exchanged ("the membrane depolarises because Na⁺ channels close").
- The standard Assertion–Reason trap. Expect it where E4 is `reasoning`.

### Pairing, order and combination traps

**`wrong_pairing`** — an item is matched to the wrong partner.
- **vs `wrong_pairing`:** if **exactly two** items have exchanged partners, that is `wrong_pairing` — the more specific value. Anything else (one item mismatched, three rotated) is `wrong_pairing`.
- Example shape: a match option in which a true event is attached to the wrong stage.

**`wrong_pairing`** — exactly two items have traded places, in a pairing or in a sequence (§ above).

**`reversed_order`** — the sequence is in the wrong order.
- vs `wrong_pairing`: a wholly or substantially rearranged sequence is `reversed_order`; the right sequence with one adjacent pair exchanged is `wrong_pairing`.
- vs `process` (E4): E4 says the student must order things; E5 says *this* option's order is wrong. Both can be true.

**`partial_combination`** — the combination is a **subset** of the correct set: every item it names is true, but it omits a true one.
- **Decision rule (mine, flagged in §6):** for a combination-option question, ask what makes *this* option wrong.
  - It **omits** a true item but includes nothing false → `partial_combination`.
  - It **includes a false item** → tag that false item's own trap (`look_alike_term`, `old_ncert_fact`, `half_true`, …), **not** `partial_combination`. The reason the option attracts is the false item looking true.
  - It does both → tag the included false item's trap; it is the stronger attraction. Say in `why` that it also omits a true item.
- **Worked real example — `Q-000015`** (statements A oestrus cycle, B menopause, C pregnancy, D menarche; correct answer option 4 = "A, C and D only"):
  - option 1 "A and D only" → `partial_combination`. Both named items are true; C is wrongly left out.
  - option 2 "A and B only" → `look_alike_term`. It includes the false statement B (menopause for menarche) — that confusion is why it attracts, not the omission.
  - option 3 "A, B and C only" → `look_alike_term`, same mechanism, same false item B.
  - This is the only fully worked real three-option E5 example available in the bank today, and the answer and statement truth-values in it were independently confirmed by B6's blind solve.

### Numerical traps

**`calculation_slip`** — a specific, identifiable wrong operation produces the option: wrong formula, missed square, dropped factor of 2, wrong power.
- **Always say which slip in `why`** (the agent prompt requires it). An unnamed slip is not a tag, it is a shrug.
- **vs `number_near_miss`:** if you can write the arithmetic that yields the option, it is `calculation_slip`. If it is merely close to the right value with no derivation behind it, it is `number_near_miss`.
- Likely shape in real data: `Q-000004` (3 : 5 for solid vs hollow sphere) — the option "5 : 3" is the ratio inverted, which is a nameable slip, so `calculation_slip`, not `semantic_reversal`. Inverting a ratio is arithmetic, not a conceptual converse.

**`number_near_miss`** — numerically close to the right answer, with no identifiable derivation (§ above).

**`unit_or_conversion`** — the right number in the wrong unit or the wrong power of ten (cm for m, kJ for J, 10³ out).
- vs `calculation_slip`: the physics is right and only the conversion is wrong.
- Watch for this in Physics, where ~80% of answers are numeric or formula-shaped.

**`sign_or_direction`** — a wrong sign, or a wrong physical direction.
- Example shape: in `Q-000003` (player turning south → east, force along north-east), "along south-west" is the exact reversal of the correct direction → `sign_or_direction`. "Along eastward" is not a reversal; it is the new velocity direction mistaken for the force direction, which is a conceptual slip — `calculation_slip` with the slip named, or `semantic_reversal` if you read it as the converse. Say which reading you used.

**`impossible_value`** — the option violates a constraint a student could have checked: a negative magnitude, an efficiency above 100%, a probability above 1, a mass smaller than its part.
- vs `number_near_miss`: `impossible_value` is catchable by inspection alone.

### Edition traps

**`old_ncert_fact`** — the option was **correct in the older NCERT edition** and is wrong in the latest. See §4 — this one has a hard precondition.

**`new_trap`** — nothing fits. One-line description; raises `E_NEW_CATEGORY` (normal).

## 4. `old_ncert_fact` — the hard precondition

**Tag `old_ncert_fact` only when a change-log entry on an evidence passage shows this option was right by the older book.** The agent is given those entries in its input precisely so this can be checked. Never infer it from the option "sounding dated".

- **The real worked example:** NCERT's age of the universe, "almost 20 billion years old" (older edition) → "almost 13.8 billion years old" (latest). Confirmed on both real books, 2026-10-09; everything else in that chapter is word-for-word identical. An option offering 20 billion years in a question whose latest answer is 13.8 is the textbook case.
- **Why it matters more than the other 18 values:** this is the only trap that tells a student the *book* changed rather than that they made a mistake. It also cross-links to D6 (`answer_changed` note type) and D7 (`D7_ANSWER_CHANGED`, high) — and an `old_ncert_fact` tag with no change-log row behind it quietly contradicts them.
- **Current state, stated plainly: `ncert/change_log.csv` contains only its header row.** Stage A9 has never written a real change-log entry, because A6–A9 have only ever run against two Biology chapters. So **today, `old_ncert_fact` is effectively untaggable and should essentially never appear.** If an agent produces it anyway, that is a signal the agent guessed — the check should treat it as such.
- When the change log does fill, `change_log_row` in `config/cascade.yaml` re-runs E5 for the affected questions automatically. Early E5 output being free of `old_ncert_fact` is expected, not a deficiency.
- **Do not confuse `old_ncert_fact` with `deleted_content`.** `deleted_content` (D6) is about a *topic* removed from the syllabus. `old_ncert_fact` is about a *fact that changed value*. A question entirely from a deleted chapter has no `old_ncert_fact` option; it has a syllabus status.

## 5. Two runs

Each wrong option is tagged twice. Disagreement goes to the adjudicator and raises `E5_ADJUDICATED` (normal). Write what you actually read — a surfaced disagreement is useful, a false agreement is not. Expect genuine disagreement to cluster on the boundaries in §3 (`calculation_slip`/`number_near_miss`, `wrong_pairing`/`wrong_pairing`, `semantic_reversal`/`sign_or_direction`); those are the places to tighten this file first once real numbers exist.

## 6. Where this draft is genuinely uncertain

1. **The `partial_combination` decision rule (§3)** is mine, not SPEC's. SPEC gives only "partial_combination" as a name. The rule matters a lot: combination-option questions are up to 19% of a recent Biology paper, so whichever way the owner rules changes many tags. The alternative reading — "`partial_combination` for *any* wrong combination option" — is simpler but throws away the information about *why* it is wrong, which is E5's whole purpose. I chose the informative reading.
2. **`look_alike_term` vs `name_variant`** rests on "same thing or different thing", which is clear in principle and arguable in practice (is a loose synonym the same thing?).
3. **`calculation_slip` vs `semantic_reversal` for an inverted ratio** (`Q-000004`'s "5 : 3"). I called it `calculation_slip`. Defensible either way.
4. **No real E5 run exists yet.** No E5 agent has ever been dispatched. The `Q-000015` worked example in §3 is reasoned from a real record with a real confirmed answer and real confirmed statement truth-values — but it is not a verified E5 output.
5. **Three traps per question may be unrealistic for Physics numericals.** Four numeric options often include one or two decoys with no mechanism at all. The §2.2 instruction (say so, `confidence: medium`) is my handling; the owner may prefer an explicit "no identifiable trap" value instead — see §7.

## 7. Proposals for the owner

Forcing a mechanism onto them produces confident-looking noise, and `new_trap` with a description is a clumsy substitute for a recurring, expected case. I have **not** added it to `config/allowed_values.yaml`; it is the owner's call. This is the one addition I would expect to earn its place quickly in Physics.
- **Rule the §6.1 `partial_combination` question.** It affects the largest number of real tags of anything in this file.
- **Leave `old_ncert_fact` alone and fix the change log instead** (§4). The value is right; the data behind it does not exist yet.
