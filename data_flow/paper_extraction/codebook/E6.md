## 1. Who decides what

| Field | Decided by | Agent involved? |
|---|---|---|
| `answer_form` | SCRIPT, from the parsed options | no |
| `negation` | SCRIPT, from `negative_words_seen` | no |
| `item_count` | SCRIPT, from parsed `statements` / `list_i` / `list_ii` | no |
| `constants_given` | SCRIPT, from stem patterns | no |
| `figure_role` | SCRIPT, from `has_figure` / `option_images` | no |
| `stem_context` | SCRIPT when exactly one pattern fires; **AGENT `e6-context-tagger` otherwise** | yes |

So **the only thing the agent is ever asked for is `stem_context`, and only in the hard cases** — when two or more context patterns fire at once and SPEC's tie-break has to be applied by judgement. §2 is therefore almost the whole job. §3 documents the script-owned fields so the owner can see and change what the script asserts, not because an agent decides them.

## 2. `stem_context` — how the stem is framed

**Allowed values:** `plain`, `case_scenario`, `experiment_setup`, `real_world`, `data_given`, `table_given`, `figure_given`, `reaction_given`, `equation_given` (`unsure` is the agent's stated fallback; it raises `E6_CONTEXT_UNSURE`, low), `historical`.

**SPEC's tie-break, verbatim: if two apply, choose the one the question cannot be answered without.**

That is the rule. Everything below is how to apply it.

### The tie-break, made decidable

When several patterns fire, sort the candidates into two kinds:

- **Material** — something in the stem that must be *read* to answer: `data_given`, `table_given`, `figure_given`, `reaction_given`, `equation_given`.
- **Framing** — how the question is dressed: `case_scenario`, `experiment_setup`, `real_world`, `historical`.

**Proposed rule (mine, not SPEC's — see §4.1): material beats framing whenever the material is load-bearing.** A story wrapped around data you must read is `data_given`; the story is removable, the data is not.

- **SPEC's own example confirms this direction:** "A biologist studied rats… natality 250…" is **`data_given`, not `case_scenario`** — the biologist is scenery, the numbers are the question.
- **When two *material* values both fire,** pick the one the answer actually comes out of. Ask: if I deleted this, could I still answer? Delete the one you can.
- **When two *framing* values both fire** and no material does, prefer the more specific: `experiment_setup` over `case_scenario` (an experiment is a kind of scenario); `historical` over `case_scenario`.
- **`plain` is never a tie-break winner.** If anything genuinely applies, `plain` is wrong.

### The values

**`plain`** — no context; the stem just asks.
- Real: `Q-000011` ("The errors in the measurement which arise due to unpredictable fluctuations…"), `Q-000015` (a statements question with no framing), `Q-000004` (a bare ratio-of-radii-of-gyration question).

**`case_scenario`** — a person, patient or situation story (a student, a couple, a farmer).
- vs `experiment_setup`: is a measurement or experiment being described, or just a situation?
- vs `data_given`: see the tie-break.
- Real: `Q-000003` — "A football player is moving southward and suddenly turns eastward…". The script reports `plain` for it (no pattern covers a sportsperson). **This is a real under-detection, not a correct answer** — see §4.2.

**`experiment_setup`** — an experiment or measurement is described (pendulum timing, metre bridge, a test on sap).
- Real near-miss: `Q-000001` — "Let a wire be suspended from the ceiling (rigid support) and stretched by a weight W…". The script reports `plain`; a person would plausibly say `experiment_setup`. §4.2.

**`real_world`** — an everyday device or application (a heater, a microwave oven).
- vs E3 `applied_context`: different tags. E6 says the *stem is framed* as an application; E3 says *NCERT itself* carries the application. A real-world-framed question resting on a bare formula is E6 `real_world` + E3 `formula`.

**`data_given`** — the stem supplies numbers that must be used.
- vs `table_given`: loose numbers in prose versus a tabulated block.

**`table_given`** — a table in the stem. The script requires table/column wording **and** parsed list rows, so a match-the-lists question's own two lists do not by themselves make it `table_given`.

**`figure_given`** — a figure accompanies the stem.
- Real: `Q-000002` — "the equivalent capacitance of the system shown in the following circuit" → `figure_given`, decided by the script (single pattern).
- Caveat worth knowing: `figure_given` describes **the stem's claim**, not whether an image file is actually present. This question's figure was missing from the scrape source for months; a real one was recovered on 2026-10-12 (`papers/figures/Q-000002.png`, from the legacy-sheet Mathpix source). The tag was correct both before and after — tag what the stem says, and let `figure_role` and the record's own `figure_path` carry whether the image exists.

**`reaction_given`** — a reaction is given in the stem.
- Real: `Q-000013` — "Identify product (A) in the following reaction: [structure … undergoing reduction with Zn-Hg and conc. HCl]". Two patterns fire (`reaction_given` + `figure_given`), so the script hands it to the agent. **This is the one real agent case in the whole bank today.**
  - **Answer: `reaction_given`.** The figure *is* the reaction scheme. What the question cannot be answered without is the reaction; "a figure exists" is the delivery mechanism, not the content. Note in `why` that both applied.
  - This is also exactly why E1 tags it `reaction_scheme` rather than `figure_to_read` — the two codebooks agree, deliberately.

**`equation_given`** — an equation the student must use is given.
- Real: `Q-000007` — "If ∮ E·dS = 0 over a surface, then:" → `equation_given`, decided by the script.
- Caveat: the real record's stem reads `"If [unreadable glyph]_S E[unreadable glyph] [unreadable glyph] dS[unreadable glyph] = 0"` — the symbols were lost in extraction (a known source defect, `docs/OPEN_QUESTIONS.md` 2026-10-12). The `= 0` survived, which is the only reason the pattern fired at all. Do not read a correct tag here as evidence the stem is intact.

**`historical`** — a scientist, discovery or date.
- Real example from SPEC: `2017#111` ("Humboldt described for the first time:"). Note E2 tags that `name_or_identify` and E3 tags it `scientist_history` — three different tags, all correct, answering three different questions.
- Caveat: the script's pattern matches any 18xx/19xx/20xx year, so a question *about* a dated event (e.g. the 2012 UN climate conference, `2015#180`) will come out `historical`. That is defensible; note that E3 calls the same question `current_affairs`.

**`unsure`** — use only when the tie-break genuinely cannot be applied. Raises `E6_CONTEXT_UNSURE` (low). Prefer a value with a stated reason over `unsure`.

## 3. The script-owned fields (documented, not decided by an agent)

### `answer_form` — what kind of thing the options are
Tested in this order, most specific first, with "most options match" as the bar:
1. `combination_code` — "A and D only"
2. `match_code` — "A-ii, B-i…"
3. `order` — a sequence (`A < B < C`, or **two or more** arrows in one option)
4. `ratio` — `a : b`
5. `number_with_unit`
6. `expression`
7. `statement` — a prose clause (≥ 5 words)
8. `term` — a short noun phrase
- `structure_image` / `graph_image` win outright when `option_images` exist. **No real question in this corpus has option images yet**, so neither value has ever been produced.
- **Three real distinctions the script encodes, each found by a real mis-tag:**
  - a LaTeX **fraction** is an `expression`, not a `ratio` — real `Q-000009` (`$-\dfrac{16Gm}{R}$`); real `Q-000004` (`3 : 5`) is the genuine ratio.
  - a LaTeX-encoded **unit** is `number_with_unit`, not `expression` — real `Q-000002` (`$2\,\mu F$`).
  - **one** arrow is a reaction, not an ordering; `order` needs two or more — real `Q-000005`.
- **Confirmed real outputs (2026-10-12):** `Q-000001` expression · `Q-000002` number_with_unit · `Q-000003` term · `Q-000004` ratio · `Q-000005` expression · `Q-000007` statement · `Q-000009` expression · `Q-000011` term · `Q-000013` expression · `Q-000015` combination_code.
- **`Q-000005`'s `expression` is the gap, not a correct tag** — see §5.

### `negation`
`none` / `single` / `double`, counting **distinct** negative words, not occurrences. `double` means two *different* negatives ("which is NOT an INCORRECT statement"), which is the genuinely trap-prone shape; the same word twice is still `single`.
- Real: `Q-000005` → `single` (`NOT`). Every other canonical record → `none`.
- E2's guard reads the same field; `codebook/E2.md` §2 notes that B3's own allowed set omits MISMATCH, so the field can be empty when the stem really does say "mismatch". E6 falls back to reading the stem for all six words, so E6's `negation` is the more reliable of the two.

### `item_count`
Counts **structurally separate** items only: B3's parsed `statements`, else `max(len(list_i), len(list_ii))`. **Items listed inside one sentence count as 0** (SPEC's own rule) — "How many plants among the following are monocots: wheat, rice, maize, pea?" is `0`, not `4`. Real: `Q-000015` → 4; all other canonical records → 0.

### `constants_given`
True on "Given:", "[Take …]", "(At. no. …)", "(Atomic number/mass …)", "Take g =", "Use x =". Real: `False` for all 10 canonical records. Expect this to rise sharply on recent papers — 12–13 constants-given questions per paper in 2026 versus 1–6 earlier.

### `figure_role`
`none` / `needed` / `options_are_figures`. **The script never returns `decorative`, by design** — calling a figure decorative asserts the question is answerable without it, which is a judgement with a real consequence (B6 refuses every `has_figure` question as image-unsafe, so a `decorative` downgrade would silently widen what the blind solver is asked to do). **Only a person in Stage F may downgrade a figure to `decorative`.** An agent must never assert it.
- Real: `needed` for `Q-000002` and `Q-000013`; `none` for the rest.

## 4. Where this draft is genuinely uncertain

1. **The material-beats-framing tie-break (§2)** is my generalisation from SPEC's single worked example (natality/mortality → `data_given`). It is consistent with that example and with `Q-000013`, but it is one rule inferred from one case. It is also the only guidance the agent will have, since the agent is called *only* on multi-hit cases.
2. **Real under-detection: the script returns `plain` on no match, without consulting the agent.** So a stem whose framing no regex covers is silently `plain`, and no flag marks it. Confirmed on real data: `Q-000003` (a football player turning — arguably `case_scenario`) and `Q-000001` (a wire suspended and loaded — arguably `experiment_setup`) both came out `plain`. Separately, `_CTX_REACTION_RE` misses the plural: real `Q-000005`'s stem says "Which of the following **reactions**…" and the arrows live in its options, which the pattern span does not include — so a question whose four options are reactions is tagged `plain`. **These are reported as build issues against `scripts/describe_tags.py`, not fixed here** (that file is outside this task's scope). 8 of 10 canonical records currently read `plain`, which is almost certainly an overcount.
3. **`data_given`'s pattern is very narrow** (`natality`, `mortality`, "the following data", "data:"). A stem that simply states three numbers will not match it. Same build-issue class as §4.2.
4. **No real E6 agent run exists yet.** The script half has been run for real (outputs above); `e6-context-tagger` has never been dispatched. `Q-000013` is the one item waiting for it.

## 5. CONFIRMED GAP — `answer_form` has no value for reaction options

Real `Q-000005`'s four options are each a chemical reaction (`CH₃CONH₂ → Br₂/KOH`, `CH₃CN → (i) LiAlH₄, (ii) H₃O⁺`, …). `answer_form`'s ten values cover `term`, `number_with_unit`, `expression`, `ratio`, `statement`, `combination_code`, `match_code`, `order`, `structure_image`, `graph_image`. **None of them is "a reaction."** The script currently reports `expression` for it, which is the least-wrong available value and still wrong: it tells a downstream consumer the options are formulae when they are transformations.

**Proposal for the owner:** add **`reaction`** to `answer_form` — "each option is a chemical reaction (reagent/arrow transformation), written as text rather than drawn". Deliberately distinct from `structure_image`, which is for drawn structures.

This is the same real gap as `codebook/E1.md` §4 (`list_of_reactions`), seen from the answer-shape side. The two should be decided together: one real question exposes both, and fixing only one leaves the other silently mis-tagging the same family of Chemistry questions. **`config/allowed_values.yaml` has not been changed — both are the owner's call.**

## 6. Other proposals for the owner

- **Fix the §4.2 under-detection before E6 runs at volume.** Either widen the patterns, or have the script hand *no-match* cases to the agent the way it hands over multi-match cases. The second is the safer change and matches how `stem_context` is meant to work: `plain` would then be a decision rather than a default. Needs a change to `scripts/describe_tags.py`, which this task may not edit.
- **Keep `figure_role: decorative` as a Stage-F-only value** (§3). Worth stating in SPEC as well, not just in the script's comments.
- **No changes proposed to `negation`, `item_count` or `constants_given`.** They are mechanical and the script's readings match SPEC exactly.
