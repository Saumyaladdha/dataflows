# E7 · Difficulty band — codebook

## 1. What this axis is, and what it is not

E7 answers: **how much work does the printed question demand?**

It does **not** answer "how hard do students find it". That number requires item-analysis data —
how many candidates answered correctly — and this project holds none. SPEC Rule 22 forbids
asserting student behaviour, and it is the rule that retired `obviously_wrong`, whose definition
was "no student who read the stem would be drawn to it". A difficulty band justified by what
students would do is the same unfalsifiable move in a new place.

So the thing measured is **solution load**: features of the question anyone can check on the page.

**Load and difficulty are not the same thing**, and this must be said wherever a band is shown. A
one-step question on an obscure fact is low load and may well be answered badly. A four-step
calculation on a familiar formula is high load and may be answered well. Nothing here separates
those. If response data ever arrives, this rubric is the thing to validate against it — which is
why `E7_difficulty_basis` stores the drivers per question rather than just the band.

## 2. Why a script owns this axis

Every driver is already decided by an earlier step:

| driver | decided by |
|---|---|
| `cognitive_demand`, `solution_structure` | ECAT (`e-category-rater`) |
| items the printed shape forces you to adjudicate | the E1 question type |
| a figure or table gates the question | the E1 overlay / the record |
| the task is negated | `task_polarity`, derived in the sheet builder |
| no part-way shortcut exists | the E5 traps |

An agent asked to band these would re-judge inputs that are already judged, and two runs would
disagree for no reason. The judgement happened in ECAT; E7 is arithmetic over it.
`scripts/rate_difficulty.py --self-test` holds the rubric's regression cases.

## 3. The rubric

| driver | points |
|---|---|
| demand `recall` | 0 |
| demand `concept_discrimination`, `application` | 1 |
| demand `calculation`, `explanatory_reasoning`, `condition_based_reasoning`, `representation_translation`, `dimensional_reasoning` | 2 |
| structure `single_step` | 0 |
| structure `several_independent_checks` | 1 |
| structure `multi_step_dependent` | 2 |
| shape adjudicates 2–3 items (`statement_i_ii`, `assertion_reason`, `multi_part_respectively`) | 1 |
| shape adjudicates 4+ items (`match_the_lists`, `arrange_in_order`, `list_of_statements`, `list_of_structures`) | 2 |
| a figure, table or experimental setup must be read before starting | 1 |
| the task is negated (`not`, `except`) | 1 |
| a trap removes any part-way shortcut (see §4) | 1 |

**Bands:** 0–2 `easy` · 3–5 `medium` · 6+ `hard`.

The weights are small integers and there are few of them, on purpose. A finer scale would imply a
precision the inputs do not have.

## 4. Traps that count as "no part-way shortcut"

`intermediate_value`, `complementary_grid`, `no_elimination_route`, `no_derivation_route`,
`partial_combination`, `sequence_endpoint_or_adjacency`, `parallel_order_decoy`,
`wrong_power_of_dependence`, `omitted_contribution`, `condition_ignored`.

Each of these means the question cannot be short-circuited: stopping early, or knowing part of it,
lands on a printed wrong option rather than on nothing. That is a property of the option set, not a
claim about students.

## 5. When there is NO band

`E7_difficulty_band` is left empty, and `E7_NOT_SCORABLE` (low) is raised, when either:

1. `review_status` is `source_incomplete` — the question is not all there, so its load cannot be
   counted (rulebook rule 5). 113 of the 580 are in this state.
2. ECAT has not filled `cognitive_demand` and `solution_structure`.

A band computed from empty inputs would be indistinguishable from a real one, and SPEC Rule 19
requires "judged and could not be decided" to look different from "never judged".

**E7 cannot run before ECAT, and v1's data cannot stand in.** v1's single E4 axis maps each label to
*either* a demand *or* a structure, never both: of the 580 questions, 261 yield a demand and 161 a
structure, and **0 yield both**. The axis split is not derivable from v1 — every row needs a real
ECAT rating.
